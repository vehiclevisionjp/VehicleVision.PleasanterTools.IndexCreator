## 稼働中の適用と選択肢 View の組込関数

2026-10-07 に次の一次情報を確認した。

- [CREATE INDEX (SQL Server)](https://learn.microsoft.com/sql/t-sql/statements/create-index-transact-sql): ONLINE = ON は開始・終了時に短時間の S ロックを取る。WAIT_AT_LOW_PRIORITY は SQL Server 2022 以降・Azure SQL で使え、ABORT_AFTER_WAIT = SELF で待機を打ち切る。省略時は待機中の要求が後続を待たせる。
- [STRING_SPLIT](https://learn.microsoft.com/sql/t-sql/functions/string-split-transact-sql): enable_ordinal は SQL Server 2022 以降・Azure SQL。互換性レベル 130 以上が必要。出力順は保証されないため ordinal を使う。
- [PostgreSQL 15 CREATE INDEX](https://www.postgresql.org/docs/15/sql-createindex.html): CONCURRENTLY は INSERT / UPDATE / DELETE を妨げないロックで作成し、既存トランザクションの終了を待つ。途中で失敗すると INVALID 索引が残る。
- [MySQL 8.4 Online DDL の性能と並行性](https://dev.mysql.com/doc/refman/8.4/en/innodb-online-ddl-performance.html): LOCK=NONE でも開始・終了時に排他メタデータロックを短時間要求し、待機中の要求は後続のトランザクションを止める。
- 固定参照コミットの Column.cs / Choice.cs / Splits.cs: SplitReturn は CRLF を LF にして分割し、各行を Trim して空行を除く。重複判定は行を `,` で単純に分けた先頭要素（AddToChoiceHash）。CreateTryCast は SQL Server が try_cast、PostgreSQL が数字判定付きの CASE、MySQL が cast(... as signed)。

SQL Server の低優先度待機には SET LOCK_TIMEOUT が効かず、MAX_DURATION（分単位）で打ち切られることを結合試験で確認した。待機中も後続の更新が通るため業務は止まらない。

- 2026-10-07: E2E 用に [playwright-core 1.63.0](https://www.npmjs.com/package/playwright-core) を開発専用の依存として追加。ライセンスは Apache-2.0（package-lock の記載と npm の登録情報で確認）、依存パッケージなし、`npm audit` の指摘なし。配布物に含まれないため NOTICE と ThirdPartyNotices には載せない。同梱ブラウザは使わず、ローカルの Chrome を使う。
