# 管理系索引の採否と検証範囲

判定日: 2026-11-02。Issue #145の検索経路調査と#161の3DB比較をまとめる。対象は固定参照 `664c833b144d9da9b6bb58e60f7e48eb01141e58` の管理系経路。以降の本体変更や任意の設定・拡張SQLまで確認済みとは扱わない。

## 製品の対応範囲

管理系の共通索引は、実装済みのSites更新差分を明示指定で扱う範囲を維持する。今回比較した他の管理系候補は、新たな自動候補・自動適用へ採用しない。利用環境ごとの個別効果を否定する判断ではなく、全利用者へ追加する条件が確定していないため。

| 経路 | 検索・標準キーと比較候補 | 判定 |
| --- | --- | --- |
| Users / Depts / Groupsの単一ID参照 | テナントとID。MySQLはID主キーと元の複合キー索引、他DBは複合主キー | 標準キーを基準とし、IDだけの重複索引を作らない |
| 一覧・編集の前後移動 | TenantIdとView条件、COUNT、件数上限、UpdatedTime順。TenantId・UpdatedTime、およびDisabledを挟む候補を比較 | 新規採用見送り。COUNTと取得の効果が異なり、上限超過では取得しない。幅あり・部分一致・DB差もある |
| 権限一覧 | PermissionsのReferenceIdで絞り、UserId・GroupId・DeptId順。標準主キーはReferenceId・DeptId・GroupId・UserId | 標準主キーで絞れるが並び順全体とは異なる。専用の並べ替え候補は未測定のため採用しない |
| 権限候補の選択 | TenantId、有効状態、正のID、複数列LIKE、UsersとDeptsのLEFT JOIN、3種別のUNION ALLと取得後の既選択除外 | 専用の全経路は未測定。Code単列の比較をこの経路全体へ流用せず、自動候補化しない |
| サイトの権限継承 | Sites.InheritPermissionとPermissions.ReferenceId、主体と所属の5分岐。Sites(TenantId,InheritPermission,SiteId)と各主体先頭の候補 | 新規採用見送り。文脈・DB・更新費用で傾向が異なる。権限値を集約する最終認可処理の代替ではない |
| 個別レコード権限 | ItemsのID主キー、SiteId、継承権限と個別権限の合成、相関EXISTS | 主体索引の新規採用見送り。重複Items索引も不採用。低位/上位ビット、多重集合、テナント境界を照合した |
| 所属・子グループの逆引き | GroupMembersとGroupChildrenの主キー、組織・ユーザー・子側からの標準逆引き | 標準キーを再利用する範囲。追加候補は設けない。大規模な再帰処理全体の性能は未確認 |
| Sitesの更新差分 | TenantIdとUpdatedTime範囲。主キーはSiteIdが間にある | `/include-site-delta`の既存対応を維持。全ての期間・投影で改善する保証ではない |
| Sitesの親階層 | TenantIdとParentId。候補はTenantId・ParentId・SiteId | 新規採用見送り。IDのみと幅ありで差があり、非特権の権限条件や取得後のメニュー順は別処理 |
| SysLogsの一覧・前後移動 | CreatedTimeの範囲と種別、COUNTと件数上限、UpdatedTime順。種別・作成日時と更新日時の候補 | 新規採用見送り。COUNTの改善が幅あり取得の改善とは限らず、DB差・追記費用もある |
| SysLogsの保持期限処理 | CreatedTimeの期限、対象IDのMIN/MAX、チャンクのID区間にも日時条件 | 追記と一括/チャンク削除を比較したが、検索用の追加索引を保守処理の改善とみなさない |
| 拡張SQL | ファイル/Extensions表のどちらでも任意SQL | 製品の自動候補・作成対象外。クエリ作成者が手動設計・保守する責務境界 |

「新規採用見送り」は現在の製品対応の判定であり、未実装のCLIを利用者へ案内したり、将来自動追加される予定として扱ったりしない。候補のDDLや合成試験の索引名は実表へ適用する手順ではない。

## 3DBの根拠と比較の単位

| 比較 | SQL Server | PostgreSQL | MySQL | 記録 |
| --- | --- | --- | --- | --- |
| 管理マスタ | COUNTやID取得の読み取りが減っても、幅ありは変わらない条件あり | COUNTのbufferが変わらない条件あり | 追加候補の参照と既存索引の交差が経路で異なる | [一覧と前後移動](管理マスタの一覧と前後移動の比較試験.md) |
| Sitesの親・差分 | 親のID取得237→4でも幅あり237のままの合成例 | 親のroot shared hit 167→122、差分半数は走査を維持 | 親は候補を使っても差分半数は主キー参照を維持 | [階層と差分](Sitesの階層と更新差分の比較試験.md) |
| 権限 | 検索時間が減っても更新時間と容量が増える例 | 個別権限で主体3索引の検索時間が増える例 | 個別権限で主体3索引の検索時間が増える例 | [補正後の比較](権限比較の標準キー補正.md) |
| SysLogs | 稀な種別のCOUNTは436→3でも幅あり436のままの合成例 | 同条件のCOUNTのbufferは変わらず、取得で増える例 | 稀な種別はrange scan、更新日時索引だけでは全件走査とSortを維持 | [一覧と保持期限](SysLogsの一覧と保持期限の比較試験.md) |

上の数字は公開可能な合成データだけの例。SQL Serverの論理読み取り、PostgreSQLのrootのbuffer、MySQLの行数や計画を同じ尺度で足さない。各試験に各候補の容量と更新費用を保存し、時間はウォームアップ後の各試行も残す。短時間の中央値だけで改善率や採用閾値を設定しない。

本体から確認できる呼出条件・件数上限と、利用環境での実行頻度を区別する。全利用者の条件別の実行頻度や読み書き比率は未確定で、DB統計の累計をそのまま毎秒の頻度とはしない。頻度が不明な候補を、件数だけで自動採用する判断は見送る。

## 比較基盤で確認した範囲

各DBに独立した架空表を作り、検索に関係する標準キー・型を揃えて比較する範囲を完了した。標準定義全体の物理レプリカを作成したという意味ではない。

- Users / Depts / Groupsは標準の通常索引とMySQLの主キー差を含め、COUNT、狭い/幅あり取得、空集合、件数上限と現在ID補完を比較した。
- Sitesは関連する通常索引の方向・一意性、親と更新差分、4種類の件数/分布を比較した。メニュー順をSQLのORDER BYへ追加していない。
- 権限比較は#194でDB別キーとbigintを補正し、BaselineVersion 2のキーをDBメタデータで照合した。5分岐、多重集合、個別取得、相関EXISTS、有効状態・別テナント、32bitを超える合成値の更新/復元を確認した。
- 所属・子グループは関連キーと正逆方向の取得結果を確認した。子グループの大規模な再帰展開の計画・費用を測ったとは扱わない。
- SysLogsはDB別主キー、種別・日時・投影・上限、追記と期限削除、残存IDと復元を比較した。削除DMLそのものの計画や本体のチャンクごとの確定境界は再現していない。

一部の試験は件数と偏りを同時に変える。全ての要因を独立に切り分けた試験、全列幅・全照合条件・無関係な標準索引・任意JOIN・同時更新・長期運用・画面全体の性能試験ではない。権限選択の複数列LIKE全体と権限一覧の専用ソートは、経路を確認したが専用の費用比較はしていない。これらを未検証のまま採用することはしない。

## 採用・適用の境界

現在の対応、所有権、標準/独自索引の再利用、明示prune、停止と回復の条件は[管理方針](../_documents/管理系共通索引の採用と管理方針.md)へ集約する。今回、新しい管理用途を採用しないため、カタログ読取対象・管理名・操作範囲を拡大しない。

新しい用途を今後採用する場合は、実際の投影・パラメータ・件数上限・利用文脈・頻度と、保持/更新負荷を揃えた根拠を示す別Issueを先に作る。Sitesでは用途単位Scopeと既存更新差分との干渉試験も必要。現在の比較完了を、未採用用途の作成・再計画Keep・pruneの実装完了と解釈しない。

## Issueの完了判定

| 条件 | 判定と証跡 |
| --- | --- |
| 操作→条件/JOIN/並び→標準キー→候補 | 上の対応表と固定参照を整理。式・LIKE・OR・アプリ処理・未専用測定を区別 |
| TenantIdと共通用途の単位 | 管理方針で列の有無を定義。物理索引の保守費用と条件/テナント別の検索を区別 |
| 3DBの基準と結果 | 関連キーの比較を各DBで実行。#194で権限側の型・キー差を補正。各試験とCIアーティファクトへ計画・照合結果を保存 |
| 件数・分布・上限・容量・更新費用 | 各合成試験へ保存。実環境の頻度未確定と全列等の制約を明示し、一律追加を不採用と判定 |
| 候補化/適用・所有権・再利用・削除・停止 | 正式な管理方針へ記録。Sites更新差分以外は今回未採用で、製品の管理範囲を増やさない |
| 実装単位と回帰試験 | #161と#194で比較基盤と補正を実施。新規採用しない用途の製品化は、必要になった場合に別Issueで審査 |
| 公開範囲 | 汎用仕様・固定参照・合成データのみ。実環境の資格情報、設定、識別子、レコード、計画を含めない |

Issue #145は管理系の候補化範囲の定義、#161は上記の関連キーを揃えた比較と採否の整理として完了とする。全管理画面の高速化・全物理条件の測定・全候補の製品化が完了したとはしない。本体全体の親#141は別途、他の子Issueと対応表を照合する。
