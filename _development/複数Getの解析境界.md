# 複数Getの解析境界

Issue #137 の結論は、最初の固定Getまでの解析を維持し、後続Getを確定候補にしないこと。
静的に引数が同じに見えても、先行呼出の成功・例外・呼出先の処理と共有状態を
この限定的なAST解析から証明できない。後続を推測で追加する実装は行わない。
診断の`first-query-only`と、後続文・catch/finallyは未解析である旨を残す。
構文解析が成功したことと、全クエリの候補化が完了したことを区別する。

| 形 | 扱い |
| --- | --- |
| 副作用のない対応宣言列から最初の固定Get | 検索先サイトの設定・件数閾値・既存の列規則でplan候補を生成 |
| 直列に並ぶ2個目以降の固定Get | 引数がリテラルでも候補化しない |
| Get前の再代入・未知呼出・分岐 | 対応宣言列ではないため候補化を停止 |
| Get後の再代入・未知呼出 | 先頭の根拠だけを残し、後続は解析済みと表示しない |
| オブジェクトの別名・共有参照 | 参照共有を安全に追跡できない場合は未解決とする |
| 結果を後続クエリに使う | 結果を評価せず、後続は候補化しない |
| 全体を囲うtry | try本文の最初のGetまで。catch/finallyや後続の到達性は保証しない |
| 呼出先スクリプト・Include・拡張 | 実行・共有状態・順序を推測せず、既存の診断と抑止を維持 |

同じサイトへの問い合わせも、サイトをまたぐ問い合わせも同じ境界とする。
将来広げるには、先行呼出を含む実行環境について副作用と例外の契約を定義する必要がある。
これはJavaScriptの任意実行やアプリ本体の意味解析へ範囲を広げる変更であり、現機能には含めない。
安全に確定できる後続形がない場合は制約と診断を成果とする、というIssueの完了条件に従う。

本体の事実確認: 2026-11-01、コミット`664c833b144d9da9b6bb58e60f7e48eb01141e58`。
[ServerScriptModelApiItems.Get](https://github.com/Implem/Implem.Pleasanter/blob/664c833b144d9da9b6bb58e60f7e48eb01141e58/Implem.Pleasanter/Libraries/ServerScripts/ServerScriptModelApiItems.cs#L20)
はホスト側のServerScriptUtilitiesへ委譲する。ローカルASTだけの純粋関数として扱わない。
本体コードのコピー・流用・依存追加は行わない。

回帰テストは３DBについて、連続する固定Get、未知呼出・再代入の前後、分岐、
try/catch/finallyで後続候補が混入しないことと診断を確認する。
索引の候補化規則・自動適用禁止・prune禁止は変更しない。
実際の呼出先を動作させた副作用の網羅検証は行っていない。
