## 本体と合成データでの追加検証

固定参照コミットの検証コピーから CodeDefiner と本体・frontend をビルドした。PostgreSQL の独立 DB IndexCreatorUpstream に本体スキーマを作成し、HTTP 経由のログイン・テンプレートからの3種別サイト作成・Results/Issues の登録・Results の更新・サイト名更新を確認した。IndexCreator の plan/apply、一覧 View・選択肢 View の生成、改名後の --prune、SQL からの更新タイトル取得も確認した。ブラウザのクリック操作を自動化した試験ではない。

10万行の合成データで SiteId と ClassA の一致条件を比較。最初の1回を除いた5回の中央値は SQL Server 5.118 → 0.838 ms、PostgreSQL 5.767 → 0.434 ms、MySQL 57.293 → 1.142 ms。いずれも1000行の一致結果を確認。ローカル環境の一例であり、実運用の性能保証にはしない。

SQL Server と MySQL でも CodeDefiner で独立した本体スキーマを作成し、HTTP 経由のログイン・テンプレートからの3種別サイト作成、索引と一覧 View の適用を確認した。MySQL の本体 owner には CREATE VIEW / SHOW VIEW がないため、View は検証用 root 接続で適用した。SQL Server の検証コンテナには全文検索機能がなく、CodeDefiner の全文索引作成だけ失敗した。通常表・索引・View の検証は成功した。MySQL の FULLTEXT カタログで NULL の方向を読み取る不具合を修正し、回帰試験を追加した。
