選択肢 View は組込関数による展開結果が、同じ設定の .NET 解析（本体と同じ規則）と一致することを 3 DB で確認した。前後の全角空白、CRLF、エスケープしたカンマ、バックスラッシュ、大文字小文字の異なる値、空の表示名、引用符を含む。View 作成後の選択肢の追加が再作成なしで反映され、後から追加した動的参照の行が除かれること、5000 件の選択肢を展開できることも確認した。

## ブラウザ操作による E2E（PostgreSQL 15・MySQL 8.4・SQL Server 2025）

固定参照コミットの本体を検証用 DB に CodeDefiner で構築し、本体を起動したまま Playwright（ローカルの Chrome、ヘッドレス）で画面を操作した。サイト・項目・保存ビュー・レコードはすべて画面から作成した。手順とスクリプトは [E2E 手順](E2E手順.md) と `_development/e2e` にある。以下は PostgreSQL の結果で、MySQL と SQL Server でも同じ手順を実施し、同じ結果を得た（MySQL は View を管理者接続で適用）。

1. テンプレートからフォルダ「E2E部門」、その配下に記録テーブル「案件」・フォルダ「サブ」（配下に記録テーブル「子テーブル」）・Wiki「手順書」、最上位に記録テーブル「トップ」を作成した。
2. 「案件」のエディタで ClassA を有効にし、詳細設定の選択肢に `10,受付,受`、`20,対応中`、`30,完了`、`40\,特殊,カンマ付き`、前後に空白のある `50,前後空白`、重複の `10,重複` を入力した。数値A を有効にし、ビュー設定で「状態=受付、数値A 降順」の保存ビューを作成し、レコードを3件登録した。
3. 本体の稼働中に `_rds`、`_views` と `_choice-lists`（`/exclude-tree` にフォルダ「サブ」、`/exclude-site` に「トップ」）を実行した。一覧 View は「案件」と「手順書」だけ、選択肢 View は「案件」だけが作成され、除外したサイトには作られなかった。
4. 適用後に画面からレコードの登録と分類の更新を行い、保存ビューの一覧が絞り込みと並べ替えどおり（300 → 250 → 200 → 100）に表示されることを確認した。
5. 選択肢 View の結果は、本体の登録画面のドロップダウン（Value と表示名）と一致した。画面で選択肢に `60,保留` と `[[Users]]` を追加すると、View を作り直さずに `60` が加わり、動的な `[[Users]]` の行は含まれなかった。

画面から項目に選択肢を設定すると、検索方法の「部分一致」が SiteSettings に保存される場合があった。この状態の分類フィルタは本体が LIKE '%値%' で検索するため、索引の候補にならないことを診断で報告した。フィルタ設定で「完全一致」に変えると `SiteId, ClassA` の索引を作成した。並べ替えの数値A は Nullable が無効のため、本体の式に合う索引がないと診断した。

## Wiki をリンク先にした選択肢（PostgreSQL 15、画面操作）

Wiki「手順書」の本文を画面で編集し、案件の項目に自項目の行と `[[Wiki の SiteId]]` を混在させて設定した。保存すると、サイト設定の Links に `{SiteId, ColumnName}` が自動で作られた。登録画面のドロップダウンは Wiki の行だけで、自項目の行は出なかった。本体は `\,` を解釈せず（値 `b\` と表示名 `c` になる）、前後の空白を除かず、先頭に空白のある重複行（a の前に空白）も除かなかった。選択肢 View は Links の項目では自項目の行を使わず、Wiki の本文の行を、`\,` のエスケープ・前後の空白の除去・先の行の採用の規則で返した。本体の改修後に画面と一致する想定で、現状の違いはこの3点だけだった。結合試験（3 DB）で、Wiki 本文の編集が View に即時反映されること、Links の複数リンクの順を確認した。JSON 形式のリンクと表へのリンクは単体チェックで停止を確認した。画面の手順は `_development/e2e/wiki.mjs`。

## JSON 形式で Wiki を指す選択肢（PostgreSQL 15、画面操作）

項目の選択肢に `[{"SiteId":Wiki の SiteId}]` を入力して保存すると、Links に `{SiteId, ColumnName, JsonFormat: true}` が作られた。登録画面のドロップダウンは空（空欄の選択肢だけ）で、この形式では Wiki の本文の行が選択肢にならなかった。選択肢 View は、`[[N]]` 形式と同じ Wiki の本文の行（`a`、`b,c`、`own1`、`z`）を返した。現行の本体との差は、この形式で View に選択肢が出る点にある。手順は `_development/e2e/wiki.mjs`（ClassC）。

## 引数の書式と列名モード

引数を Implem.CodeDefiner の `ArgsType`（`Starter.cs`）と同じ書式にそろえた。操作の後ろに `/` で始まるオプションを並べ、値のあるものは次の引数を値にする。パスを取るもの（`/p`、`/sites`、`/output`）は `/` で始まる値も消費する（Linux の絶対パス）。CodeDefiner が別の意味で使う文字（`l z s r t h b i e`）は使わず、`/p /y /f /c` だけを同じ意味で共有する。旧書式（`--` と `-p` / `-y`）は受け付けず、`Options start with /` と案内して停止する。一覧 View の `/names column` は、3 DB で View を作成し、列名が ColumnName（TitleBody を含む）になること、Items のタイトルを返すことを結合試験で確認した。配置試験は13件。
