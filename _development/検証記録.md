## 本体と合成データでの追加検証

固定参照コミットの検証コピーから CodeDefiner と本体・frontend をビルドした。PostgreSQL の独立 DB IndexCreatorUpstream に本体スキーマを作成し、HTTP 経由のログイン・テンプレートからの3種別サイト作成・Results/Issues の登録・Results の更新・サイト名更新を確認した。IndexCreator の plan/apply、一覧 View・選択肢 View の生成、改名後の --prune、SQL からの更新タイトル取得も確認した。ブラウザのクリック操作を自動化した試験ではない。

10万行の合成データで SiteId と ClassA の一致条件を比較。最初の1回を除いた5回の中央値は SQL Server 5.118 → 0.838 ms、PostgreSQL 5.767 → 0.434 ms、MySQL 57.293 → 1.142 ms。いずれも1000行の一致結果を確認。ローカル環境の一例であり、実運用の性能保証にはしない。

選択肢 View は組込関数による展開結果が、同じ設定の .NET 解析（本体と同じ規則）と一致することを 3 DB で確認した。前後の全角空白、CRLF、エスケープしたカンマ、バックスラッシュ、大文字小文字の異なる値、空の表示名、引用符を含む。View 作成後の選択肢の追加が再作成なしで反映され、後から追加した動的参照の行が除かれること、5000 件の選択肢を展開できることも確認した。

稼働中の適用は、別セッションが取引中にロックを保持した状態で確認した。PostgreSQL の View 置換と MySQL の索引追加はロック待ちの上限で中止し、2回の再試行後に停止して、途中の索引を残さなかった。SQL Server 2025 では低優先度で待機している間に別セッションの更新が5秒以内に完了し、ロック解放後に索引が作成された。フォルダ単位・サイト単位の除外は単体チェックで、Sites.ParentId の読み取りは3 DB で確認した。

SQL Server と MySQL でも CodeDefiner で独立した本体スキーマを作成し、HTTP 経由のログイン・テンプレートからの3種別サイト作成、索引と一覧 View の適用を確認した。MySQL の本体 owner には CREATE VIEW / SHOW VIEW がないため、View は検証用 root 接続で適用した。SQL Server の検証コンテナには全文検索機能がなく、CodeDefiner の全文索引作成だけ失敗した。通常表・索引・View の検証は成功した。MySQL の FULLTEXT カタログで NULL の方向を読み取る不具合を修正し、回帰試験を追加した。

## ブラウザ操作による E2E（PostgreSQL 15）

固定参照コミットの本体を検証用 PostgreSQL に CodeDefiner で構築し、本体を起動したまま Playwright（ローカルの Chrome、ヘッドレス）で画面を操作した。サイト・項目・保存ビュー・レコードはすべて画面から作成した。

1. テンプレートからフォルダ「E2E部門」、その配下に記録テーブル「案件」・フォルダ「サブ」（配下に記録テーブル「子テーブル」）・Wiki「手順書」、最上位に記録テーブル「トップ」を作成した。
2. 「案件」のエディタで ClassA を有効にし、詳細設定の選択肢に `10,受付,受`、`20,対応中`、`30,完了`、`40\,特殊,カンマ付き`、前後に空白のある `50,前後空白`、重複の `10,重複` を入力した。数値A を有効にし、ビュー設定で「状態=受付、数値A 降順」の保存ビューを作成し、レコードを3件登録した。
3. 本体の稼働中に `_rds`、`_views` と `_choice-lists`（`--exclude-tree` にフォルダ「サブ」、`--exclude-site` に「トップ」）を実行した。一覧 View は「案件」と「手順書」だけ、選択肢 View は「案件」だけが作成され、除外したサイトには作られなかった。
4. 適用後に画面からレコードの登録と分類の更新を行い、保存ビューの一覧が絞り込みと並べ替えどおり（300 → 250 → 200 → 100）に表示されることを確認した。
5. 選択肢 View の結果は、本体の登録画面のドロップダウン（Value と表示名）と一致した。画面で選択肢に `60,保留` と `[[Users]]` を追加すると、View を作り直さずに `60` が加わり、動的な `[[Users]]` の行は含まれなかった。
6. `_views --prune` に `--exclude-site` で Wiki を加えると Wiki の一覧 View だけが削除され、選択肢 View は残った。

画面から項目に選択肢を設定すると、検索方法の「部分一致」が SiteSettings に保存される場合があった。この状態の分類フィルタは本体が LIKE '%値%' で検索するため、索引の候補にならないことを診断で報告した。フィルタ設定で「完全一致」に変えると `SiteId, ClassA` の索引を作成した。並べ替えの数値A は Nullable が無効のため、本体の式に合う索引がないと診断した。
