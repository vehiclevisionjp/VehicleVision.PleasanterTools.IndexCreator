# インデックス・View・ログの生成ルール

インデックス・一覧 View・選択肢 View は、サイト設定から次のルールで機械的に生成します。手動で名前を変更すると、必要な対象として照合できなくなるため、名前を保持して運用してください。

## 共通

ReferenceType は Results / Issues / Wikis、SiteId は数値のサイト ID です。3 DB で同じ命名規則を使い、UTF-8 で最大63バイトに収めます。DB 上では名前を引用して扱います。日本語を含む名前は、コンソールと実行ログでは Unicode エスケープで表示します。

サイト名は Sites.Title を Unicode NFC に正規化し、文字・数字・`_`・`-` 以外の連続部分を `_` に変換して、両端の `_` を取り除きます。空なら Untitled を使います。上限を超える場合はサイト名の末尾を文字単位で短縮します。サイト ID と、選択肢の項目名は保持します。

例えば `案件 / 一覧` は `案件_一覧` になります。固定部分だけで63バイト以上になる場合は生成を停止します。

## インデックス

```text
IX_vvplic_{ReferenceType}_{SiteId}_{Purpose}_{Hash16}
```

- Purpose はキー列のうち SiteId 以外の先頭列名です。例：UpdatedTime、ClassA、Status。
- Hash16 は物理テーブル名・キー列・方向・MySQL の prefix 長・PostgreSQL の pattern 指定から生成する SHA-256 の先頭16桁の小文字16進表記です。サイト名とサイト ID はハッシュに含めません。
- 同じ物理テーブルで同じ定義を使う候補は共有します。同じ候補を生成したサイトの最小 SiteId を名前に採用します。別候補の先頭部分だけで足りる候補はまとめます。
- 長さを超える場合は Purpose の末尾を短縮します。ReferenceType、SiteId、Hash16 は保持します。

例えば、Results のサイト100で ClassA を先頭の絞り込みキーに使う場合は `IX_vvplic_Results_100_ClassA_{Hash16}` です。列順や方向を変えるとハッシュも変わります。

### キー列の決定

- 対象は `/min-records` 以上のレコード数を持つサイトです。既定は10000件です。この件数条件は一覧 View と選択肢 View には適用しません。
- SQL Server / MySQL では `SiteId, UpdatedTime DESC, ResultId DESC` のような既定順序の候補を作ります。末尾の ID は参照種別により ResultId / IssueId / WikiId です。PostgreSQL はこの既定候補を追加しません。
- 保存ビューの条件から、SiteId、完全一致の列（列名の順）、範囲・前方一致の列の順に並べます。範囲列が複数ある場合は1列ずつ別の候補にします。範囲列がない場合は利用可能な並べ替え列と既定のタイブレーカを続けます。同じ列は最初の指定を残します。
- 自分が担当（`Own`）は `Manager = 自分 OR Owner = 自分` に対応して、各分岐の列を完全一致キーに加えた候補を生成します。単一の `Manager, Owner` 複合キーとして OR 全体をカバーしたとは扱いません。
- Issues の期限が近い（`NearCompletionTime`）は `CompletionTime`、期限超過（`Overdue`）は `CompletionTime` と `Status` を別の範囲候補にします。`UseNegativeFilters=true` かつ該当する `ViewFilters_...` が `ColumnFilterNegatives` にある場合は、その条件を候補に加えません。
- リンク・サマリには `SiteId, リンク項目` を候補にします。`/include-filter-columns` を指定すると、フィルタ項目の完全一致候補も追加します。
- リンク選択肢の `Links[].View` にある条件・明示的な並べ替えは、リンク先の Results / Issues に対して解析します。リンク元の件数が少なくても解析しますが、リンク先には `/min-records` を適用します。既定の選択肢順は Items.Title のため、UpdatedTime の並べ替えやタイブレーカを補いません。リンク先が取得できない場合や件数不足の場合は診断します。Wiki 本文の選択肢にはこの処理を適用しません。
- 項目連携は `RelatingColumns` の隣接する親子項目からリンク先をたどり、子マスタ側の親へのリンク列を調べます。単一選択なら `SiteId, 親リンク列, ID` を候補にします。本体の数値変換は残るため、変換後の値による索引検索をカバーしたとは扱いません。MySQL の prefix は値全体を保持せず、読み取り全体のカバーも保証しません。複数選択・件数不足・設定不足は理由を診断し、項目連携専用の候補を追加しません。通常のリンク候補は独立した規則で残ります。
- 子マスタが同じ親マスタへのリンクを複数持つ場合は、保存された `EditorColumnHash` の項目順を優先します。その順序が得られない場合は推測せず、診断して項目連携専用の候補を追加しません。
- MySQL の Class 項目には `/mysql-prefix` の長さを使います（既定100文字）。PostgreSQL の前方一致には pattern 指定を付けます。
- 否定・任意の OR・部分一致・複数選択・リンク先の条件、式を必要とする並べ替えは、通常の B-tree 候補から除外して診断します。`Own` の既知の OR 分岐だけは前述の規則で対応します。

### ハッシュの入力

UTF-8 で次の文字列をハッシュ化します。Direction は `A`（昇順）/ `D`（降順）、Prefix は10進数、Pattern は `True` / `False` です。区切り文字も入力に含めます。

```text
Table|Column:Direction:Prefix:Pattern|Column:Direction:Prefix:Pattern|...
Results|SiteId:A:0:False|ClassA:A:0:False|UpdatedTime:D:0:False|ResultId:D:0:False
```

Purpose に使える SiteId 以外の列がない場合は SiteId を使います。インデックスは物理テーブル全体に作成し、名前に含める SiteId は候補の代表サイトを示します。

既存索引のキーが必要な定義をカバーする場合は追加しません。同名の管理索引は定義の一致を要求します。管理対象の判定には接頭辞だけでなく、参照種別・ID・用途・16桁のハッシュ・長さの形式も使います。

## 一覧 View

```text
View_vvplic_{ReferenceType}_{SiteId}_{SiteName}
```

列は GridColumns の順序で生成します。GridColumns が省略されている場合は本体の列定義の GridEnabled と GridColumn を使います。本体の共通列定義も読み、同名の項目がある場合は参照種別固有の定義を優先します。

列名は、その項目の GridLabelText → LabelText → 本体の列定義の LabelText → 物理列名の順で決定します。`/names column` を指定した場合は、表示名を使わず ColumnName（物理列名）にします。同じ列名が重なる場合は `表示名 (物理列名)` を使います。それでも重なる場合や DB の列名制限を超える場合は停止します。

Title と TitleBody は Items.Title を取得し、それ以外は実在する物理列を取得します。サイト ID で行を絞ります。リンク先・計算項目など、対応する式がない列を黙って省略することはありません。値の表示変換、ユーザー権限、保存ビューの条件、取得順序は SQL View に含めません。

## 選択肢 View

```text
View_vvplic_ChoiceList_{ReferenceType}_{SiteId}_{ColumnName}_{SiteName}
```

ChoicesText を持つ項目ごとに1つ生成します。同じサイトの ClassA と ClassB は別の View です。例えばサイト100の ClassA は `View_vvplic_ChoiceList_Results_100_ClassA_案件一覧`、ClassB は `View_vvplic_ChoiceList_Results_100_ClassB_案件一覧` です。

列は Pleasanter の Choice のプロパティ名と同じ3列で固定します。

| 順序 | 列 | 生成方法 |
| --- | --- | --- |
| 1 | Value | 選択肢のキー。区切った1番目の値 |
| 2 | Text | 表示名。2番目が空なら Value |
| 3 | TextMini | 短縮名。3番目が空なら Text |

View は Sites.SiteSettings の ChoicesText を参照のたびに DB の組込関数で展開します。選択肢を編集すると、View を作り直さなくても結果に反映されます。レコードがないサイトでも選択肢を取得できます。SQL View は取得順序を保証しません。

ChoicesText を改行で行に分け、行の前後の空白と空行を除きます。`\` が前にないカンマで区切り、`\,` はカンマに戻して値に含めます。本体の General.json の既定（区切り `(?<!\\),`、置換 `\\(,)` → `$1`）と同じ規則です。General.json でこれらを変更している場合は、DB 側で同じ結果を保証できないため生成を停止します。設定フォルダの解決は `/p` と Env.ParametersPath に従います。4番目以降の CSS・スタイルなどは列にしません。

例えば `100,受付,受` は Value=`100`、Text=`受付`、TextMini=`受`、`200,完了` は Value=`200`、Text=`完了`、TextMini=`完了` になります。

同じ項目で、行をカンマで分けた先頭部分が重なる場合は、本体と同じく最初の行を採用します。比較は大文字と小文字を区別します。別の項目の同じ Value は、それぞれの View に保持します。固定選択肢がない項目、ControlType が空または ChoicesText 以外の項目には View を作りません。Links に SiteId のある設定を持つ項目はリンク項目で、リンク先が Wiki であれば、その本文の行（ChoicesText と同じ規則）を、Links の順に展開します。リンク項目では、リンク以外の行を使いません（本体と同じ）。Links のない動的な参照（`[[Users]]` など）、リンク先が表（対象外）または不明の場合は、計画時に生成を停止します。JSON 形式のリンク（`JsonFormat`）も、リンク先が Wiki なら同じ規則で展開します。View の作成後に追加された動的な参照の行は、View の結果から除きます。詳しくは [選択肢 View ガイド](選択肢Viewガイド.md#wiki-をリンク先にした選択肢) を参照してください。

必要な DB の機能は次のとおりです。満たさない SQL Server では適用前に停止します。

| DB | 使う組込関数 | 要件 |
| --- | --- | --- |
| SQL Server | OPENJSON、STRING_SPLIT（ordinal）、PIVOT、TRIM | SQL Server 2022 以降または Azure SQL、互換性レベル 130 以上 |
| PostgreSQL | jsonb_array_elements、regexp_split_to_table、regexp_split_to_array、DISTINCT ON | 検証は PostgreSQL 15 |
| MySQL | JSON_TABLE、SUBSTRING_INDEX、REGEXP_REPLACE、ROW_NUMBER | 検証は MySQL 8.4 |

## 設定を変更した場合

インデックスの定義変更は新しいハッシュの名前になります。サイト名の変更は新しい View 名になります。表示列・項目ラベルは、同じ名前の View を更新します。選択肢の内容は再実行なしで反映されます。選択肢を持つ項目やサイトを追加した場合は再実行します。

古い管理対象は `/prune` を指定した場合に整理します。一覧 View と選択肢 View は別々に整理するため、`_views /prune` は選択肢 View を削除しません。PostgreSQL の列構成変更に必要な操作は [サイト View ガイド](サイトViewガイド.md) を参照してください。

## 実行ログ

```text
logs/VehicleVision.PleasanterTools.IndexCreator_yyyyMMdd_HHmmss.log
```

起動時の作業フォルダを基準に logs を作ります。日時は起動時のローカル時刻で、年・月・日・時・分・秒をゼロ埋めします。同じ秒に起動した実行は同じファイルに追記します。形式は CodeDefiner に合わせ、製品名は IndexCreator の名前を使います。

NLog で UTF-8（BOM なし）のメッセージを保存します。出力は英語固定で、接続文字列や例外の詳細は含めません。自動削除は行いません。運用方法は [利用ガイド](利用ガイド.md#実行ログ) を参照してください。
