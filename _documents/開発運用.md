# 開発運用

正式な規約は [.github/copilot-instructions.md](../.github/copilot-instructions.md)。AGENTS.md と CLAUDE.md は同じ規約を参照する。

開発基準は develop。通常の変更は Issue → 作業ブランチ → 検証 → Draft PR。master はリリース確定版のみ。初期シードのみ直接作成し、利用者の DB に変更を加える実装の PR はレビューを待つ。

Advanced Security、secret scanning、push protection、develop/master/タグの ruleset はユーザーが設定する。既存の保護ルールを自動で緩和しない。CI 名を required checks に登録する場合は、実行済みチェックを GitHub 側で選ぶ。

参照サブモジュールの定期更新は GitHub App を使い、更新 Issue と Draft PR を作る。設定名は既存プロジェクトと共通の `MY_REPO_AUTOMATION_BOT_CLIENT_ID`（Actions variable）と `MY_REPO_AUTOMATION_BOT_PRIVATE_KEY`（Actions secret）。このリポジトリで登録済みであることを名前だけ確認した。秘密値は読まない。

更新チェックは上流の `main` の先頭と固定コミットを突き合わせる（リリースタグは表示のためだけに使う）。開いている更新 PR があれば、同じ PR へコミットを足してポインタを最新へ進める（更新のたびに別の PR を作らない）。`main` はリリース前の変更を含むため、文書に版を書くときは確認したコミットと `<Version>` を書く。Dependabot の gitsubmodule には置き換えていない（2026-02 にタグの扱いが変わったばかりで、追従ブランチの決め方と未マージ PR の更新の仕方が公式に書かれておらず、動作を手元で確かめられないため）。変更時は更新 PR の CI と本体定義の互換性を確認してからマージする。自動マージしない。

Issue/PR へ秘密値・実運用設定・DB 例外全文を貼らない。CI の既知の検証用パスワードは compose 専用で、本番に流用しない。

共有メモリは [Internal リポジトリ](https://github.com/vehiclevisionjp/VehicleVision.PleasanterTools.IndexCreator.ClaudeMemory)。利用者の個別ハーネス設定は本体リポジトリへコミットしない。メモリに正式規約を複製せず、要点と参照先を残す。
