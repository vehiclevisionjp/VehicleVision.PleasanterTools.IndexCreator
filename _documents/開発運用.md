# 開発運用

正式な規約は [.github/copilot-instructions.md](../.github/copilot-instructions.md)。AGENTS.md と CLAUDE.md は同じ規約を参照する。

開発基準は develop。通常の変更は Issue → 作業ブランチ → 検証 → Draft PR。master はリリース確定版のみ。初期シードのみ直接作成し、利用者の DB に変更を加える実装の PR はレビューを待つ。

Advanced Security、secret scanning、push protection、develop/master/タグの ruleset はユーザーが設定する。既存の保護ルールを自動で緩和しない。CI 名を required checks に登録する場合は、実行済みチェックを GitHub 側で選ぶ。

参照サブモジュールの定期更新は GitHub App を使い、更新 Issue と Draft PR を作る。設定名は既存プロジェクトと共通の `MY_REPO_AUTOMATION_BOT_CLIENT_ID`（Actions variable）と `MY_REPO_AUTOMATION_BOT_PRIVATE_KEY`（Actions secret）。このリポジトリで登録済みであることを名前だけ確認した。秘密値は読まない。

更新チェックは上流の `main` の先頭と固定コミットを突き合わせる（リリースタグは表示のためだけに使う）。開いている更新 PR があれば、同じ PR へコミットを足してポインタを最新へ進める（更新のたびに別の PR を作らない）。`main` はリリース前の変更を含むため、文書に版を書くときは確認したコミットと `<Version>` を書く。Dependabot の gitsubmodule には置き換えていない（2026-02 にタグの扱いが変わったばかりで、追従ブランチの決め方と未マージ PR の更新の仕方が公式に書かれておらず、動作を手元で確かめられないため）。変更時は更新 PR の CI と本体定義の互換性を確認してからマージする。自動マージしない。

Issue/PR へ秘密値・実運用設定・DB 例外全文を貼らない。CI の既知の検証用パスワードは compose 専用で、本番に流用しない。

共有メモリは [Internal リポジトリ](https://github.com/vehiclevisionjp/VehicleVision.PleasanterTools.IndexCreator.ClaudeMemory)。利用者の個別ハーネス設定は本体リポジトリへコミットしない。メモリに正式規約を複製せず、要点と参照先を残す。

## CLA の運用

公開リポジトリへの貢献は、取り込む前に CLA の同意と許諾権限を確認する。
現在は AGPL-3.0-or-later 単独であり、CLA は将来の商用提供を含むライセンス選択の余地を残すためのもの。
[CLA 草案](../CLA.md) と [貢献手順](../CONTRIBUTING.md) を参照する。
**正式な同意を受け付ける前に、法務確認を受けて草案の但し書きを外す。**

### 初期配置と必須化

`cla` は PR の **base コミット**の `.github/cla/signed.yml` だけを読む。
PR のコードやスクリプトは実行せず、外部の CLA サービスも利用しない。
PR 内で署名一覧を変更しても、その PR 自体の判定には使わない。

1. ワークフローと署名一覧を、必須化より先に `develop` へ配置する。
   初期署名はユーザー指示により `pmc-ko` の 2026-10-22 の法人記録 1 件だけとする
2. `master` についても、必須化より先にワークフローと署名一覧を通常の PR で反映する。
   初回の `develop` → `master` の PR に `cla` を先に要求しない
3. 配置と法務確認を終えた後、管理者が別作業として `cla` の必須化を判断する。
   この導入では GitHub の設定・ルールセットを変更しない

base に署名一覧が無いと `cla` は失敗する。導入 PR もこの制約を受ける可能性があるため、本文に明記する。
必須化前の配置順序は未署名の貢献を許容する例外ではない。

### 管理者による署名の確認

1. 「CLA への署名」の Issue で、ログイン名・本人の同意・貢献を許諾する権限を確認する。
   会社の業務としての貢献なら、法人用の同意・勤務先の承認・法人を代表する権限も確認する
2. 管理者が `.github/cla/signed.yml` に `login`・`signed`（YYYY-MM-DD）・
   `type`（`individual` / `corporate`）・`note` を記録する。
   同意の Issue は管理者の変更 PR から参照し、秘密情報や非公開の契約書は記録しない
3. 対象 base ブランチへ一覧を取り込んだ後、貢献 PR を更新してチェックを再実行する。
   `develop` と `master` の署名一覧は別々に確認し、通常の PR で同期する

今回の初期記録は Issue #79 のユーザー指示に基づく。署名 Issue や法務確認の完了を意味しない。
一覧から削除しても、それ以前の貢献に対する許諾は CLA の条文に従う。
チェック対象は PR 作者のログイン名のみで、共同著作者全員の権利を自動確認するものではない。
管理者は実際の貢献の権利も取り込み時に確認する。

bot の除外は `dependabot[bot]`・`github-actions[bot]`・`my-repo-automation-bot[bot]` の完全一致のみ。
署名一覧の存在確認後に除外し、ジョブを省略せず成功を報告する。未知の bot は自動除外しない。

### 法務確認事項

Template の草案を本リポジトリに合わせ、著作権・特許・商用再許諾を含む条文を維持した。
許諾先の「当社」は株式会社ピー・エム・シー ITソリューション事業部に統一した
（ユーザー指示 2026-10-22）。
商用再許諾・特許許諾の範囲は引き続き法務確認が必要。
法人・個人双方の同意、代表権、従業員の貢献の対象範囲、初期記録の裏付けも確認する。
条文や許諾先を開発判断で修正せず、正式な同意受付と将来のライセンス変更は法務判断を待つ。
