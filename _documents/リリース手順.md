# リリース手順

バージョンは vX.Y.Z。初期実装は 0.1.0 とし、正式なリリースはレビューと対象 Pleasanter 版での実機確認が済んでから作ります。

1. develop の CI、3 DB 検証、依存監査、CodeQL を確認する。
2. 本体 UI から作った代表的なビューに対して plan/apply を実行し、追加前後の性能と登録・更新を計測する。未対応と既知の制約をリリースノートに記載する。
3. Directory.Build.props と package.json のバージョン、README と運用手順を更新する。
4. develop から master への PR を作り、ユーザーが設定した保護ルールに従ってマージする。
5. master の確定コミットに vX.Y.Z タグを付ける。Release Actions が下書きを作り、OS・アーキテクチャ共通の ZIP と SHA256 を添付する。
6. 下書きのソース・内容・SHA256 と公開ライセンスを確認し、公開する。

ZIP は .NET 10 Runtime が必要なフレームワーク依存版。
`IndexCreator` フォルダを含み、本体・CodeDefiner と同階層へ展開する。
ソースは GitHub のタグから取得する。
オンデマンド取得する非追跡の本体参照ソース・共有先・Git メタデータは配布 ZIP に含めない。

正式リリース用タグは検証前に作らない。初期 PR のレビュー用配布物は CI の artifact を使う。

## NuGet（dotnet tool）の公開

GitHub Release の ZIP に加えて、NuGet パッケージ `VehicleVision.PleasanterTools.IndexCreator`（dotnet tool）を nuget.org へ出す。
タグの実行で `release.yml` の `publish-nuget` ジョブが公開する。**公開した版は取り消せない**（nuget.org では削除できず、非推奨にできるだけ）。タグも付け直せない。

### パッケージの形

- パッケージ ID は `VehicleVision.PleasanterTools.IndexCreator`、コマンド名は `index-creator`。
- RID 非依存・フレームワーク依存の単一パッケージ（`tools/net10.0/any/`）。利用側に .NET Runtime 10 が要る。
- .NET 10 SDK は `RuntimeIdentifiers` を持つ tool を RID 別パッケージへ分割する。ZIP 用の `RuntimeIdentifiers` は残しつつ、
  `dotnet pack` の間だけ外す（`IndexCreator.csproj`）。そのため pack は restore 済みで `--no-restore` を付ける。
  付けないと `packages.lock.json` が書き換わる。
- 同梱するのは README.md・LICENSING.md（`PackageLicenseFile`）・LICENSE-COMMERCIAL.md・LICENSE・NOTICE・ThirdPartyNotices.txt。
- 版は `Directory.Build.props` の `Version` とタグ。pack は `-p:Version=<タグから v を除いた値>` で行う。

手元の確認:

```powershell
dotnet restore --locked-mode
dotnet build -c Release --no-restore
dotnet pack src/IndexCreator/IndexCreator.csproj -c Release --no-restore -p:Version=0.0.0-local -o artifacts/nuget
dotnet tool install --tool-path ./tool --add-source artifacts/nuget VehicleVision.PleasanterTools.IndexCreator --version 0.0.0-local
```

### release.yml の構成

- `package`: restore（locked）・ビルド・テスト・ZIP・nupkg の pack と artifact 化。タグでは下書きリリースも作る。
  タグを打たない手動実行（Actions の「Run workflow」）は、ここまでの検証だけで、リリースも公開もしない（dry-run）。
- `publish-nuget`: `package` の後、タグの実行のときだけ動く。
  master 包含・タグと `Version` の一致・nupkg の版を確認し、Trusted Publishing で `dotnet nuget push` する。

初回は、有効化の前に手動実行の dry-run を行い、artifact の nupkg の中身を確認する。

### 公開の前提

1. **SNI の法務確認。** nupkg には `Microsoft.Data.SqlClient.SNI.runtime` のネイティブ dll
   （`runtimes/win-x86|win-x64|win-arm64/native/Microsoft.Data.SqlClient.SNI.dll`）が入る。
   [LICENSING.md](../LICENSING.md) の例外の頒布条件を NuGet 経由の頒布が満たすことは、2026-10-30 に確認済み。
2. nuget.org の Trusted Publishing のポリシーを作る（下表。Package Owner を間違えると、ID 予約の 409 で拒否される）。
3. 変数 `NUGET_ORG_USER`（公開用の共有アカウントの nuget.org プロフィール名。メールアドレスではない）を、このリポジトリへ共有する。

| 項目 | 値 |
| --- | --- |
| Package Owner | 組織 `vehiclevisionjp` |
| Repository Owner | `vehiclevisionjp` |
| Repository | `VehicleVision.PleasanterTools.IndexCreator` |
| Workflow File | `release.yml` |
| Environment | 空 |
| Scopes | Push new packages and package versions |
| Glob | `VehicleVision.PleasanterTools.IndexCreator` |

公開後の導入は `dotnet tool install -g VehicleVision.PleasanterTools.IndexCreator`。nuget.org の一覧へ反映されるまで数分かかる。
