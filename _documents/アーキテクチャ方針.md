# アーキテクチャ方針

参照日: 2026-10-07。

## 要件と構成

.NET 10 の単独コンソールアプリ。AGPL-3.0-or-later。配布フォルダは `IndexCreator`、本体と CodeDefiner の兄弟。標準索引・列・テーブルの管理は本体に任せ、サイト設定に対応した追加索引だけを管理する。

`Options` が引数、`Configuration` が本体設定、`Planner` が候補、`Reconciler` が既存索引との比較、`SqlDialect` が DDL、`Database` が接続・カタログ検査・適用を担当する。Pleasanter のアセンブリを参照しない。

## 対応範囲

| 設定・処理 | 初版 |
| --- | --- |
| Results / Issues / Wikis | 対応 |
| SQL Server / MySQL の既定並べ替え | SiteId, UpdatedTime DESC, ID DESC |
| PostgreSQL の既定並べ替え | 標準 PK で足りるため追加しない |
| 完全一致 | SiteId, 等価列（名前順）, 並べ替え, タイブレーカ |
| 範囲・前方一致 | 等価列の後ろに最初の範囲列。並べ替えのカバーを主張しない |
| PostgreSQL の前方一致 | varchar_pattern_ops |
| MySQL 分類項目 | TEXT の prefix index |
| 数値 Nullable=true・日付・非 NULL の標準列の並べ替え | 対応 |
| リンク・サマリ | SiteId, リンク項目 |
| and_ グループ | 展開して解析 |
| 否定・OR・リンク先条件・複数選択・部分一致 | 候補から外して診断 |
| ISNULL / coalesce / ifnull の並べ替え | 式索引は未対応として診断 |
| 親から子への JOIN | 式索引は未対応として診断 |
| Items.Title の追加索引 | 初版では作らない |
| 手動の一時条件・API 条件・拡張 SQL | SiteSettings にないため対象外 |

拡張列は Class/Num/Date/Check の A〜Z と 3 桁番号に対応。カスタム定義での型・Nullable の上書きは初版では自動追随しない。実 DB の列名を検査するが、型・選択度・実行計画の最適性まで保証しない。

## 管理と再実行

名前は `IX_vvplic_{ReferenceType}_{SiteId}_{用途}_{SHA256 の先頭16桁}`。ReferenceType は Results / Issues / Wikis。用途は SiteId 以外の先頭キー列。キー列・方向・MySQL prefix 長・PostgreSQL opclass をハッシュに含める。ハッシュにサイト ID は含めず、同じ物理テーブルに対する同じ候補は共有し、候補を生成した最小のサイト ID を代表にする。名前は ASCII で最大 63 文字。用途部分だけを短縮し、ID とハッシュは保持する。前方部分が別候補に含まれるものはまとめる。

既存索引はカタログから取得。同名の管理索引は定義一致を要求する。管理外の通常 B-tree が先頭キーをカバーすれば維持扱い。フィルタ索引、式索引、別照合順序、不可視・無効索引は通常の代替にしない。INCLUDE はキーの比較から除く。

`--prune` がなければ削除しない。必要な新規索引をすべて作成・検証後、現版の厳密な命名規則に一致する不要索引だけ削除する。新しい候補を古い管理索引で代替しないので、削除後の不足を防げる。`/f` と無効索引修復は同名の管理対象を DROP → CREATE する。失敗時は再実行で回復し、DB 全体のトランザクションにはしない。

追加テーブル、管理用 DB、状態ファイルは不要。実 DB の索引を毎回正とするため、CodeDefiner のテーブル再構成による索引消失から再実行で回復する。記事の `ixc_` 名は別ツールの管理対象なので削除しない。

適用中は DB のセッションロック。設定不正・同名定義衝突・存在しない列では変更前に停止。サイト設定のスナップショットは適用開始前と不要索引削除前に確認する。ただし、他プロセスの CodeDefiner やサイト編集を完全にはロックできないため同時実行しない。

## 検証の範囲

単体チェックと SQL Server 2025 Developer・PostgreSQL 15・MySQL 8.4 の専用 DB による DDL 結合チェックを用意した。作成、再実行、設定変更に相当する新候補への切替、不要管理索引の削除、標準索引保護、消失後の再作成、多重実行防止を検証する。PostgreSQL では pattern opclass のカタログ往復も検証する。

検証条件と結果は開発者向けの [検証記録](../_development/検証記録.md) に記載する。実運用投入前に対象バージョンと代表ビューで測定する。

## サイト SQL View

`ViewPlanner` は GridColumns の順序と GridLabelText / LabelText を読み、Sites.Title から `View_vvplic_{ReferenceType}_{SiteId}_{SiteName}` を生成する。既定列は本体の Definition_Column を参照する。Title は Items に結合し、それ以外は実在する物理列を投影する。制限と運用は [サイト View ガイド](サイトViewガイド.md) に記載する。

PostgreSQL の列構成変更は通常停止する。明示の `/f` では単一 View のトランザクションで DROP / CREATE とテーブル単位の外部 GRANT 復元を行う。列単位の権限は自動移行せず停止。CASCADE は使わず、依存がある場合はロールバックする。

## 実行ログ

`RuntimeLog` が NLog 6.2.1 を使ってコンソールとファイルへ出力する。CodeDefiner Starter.cs に合わせ、作業フォルダの logs に製品名とローカル開始日時 yyyyMMdd_HHmmss を使ったファイルを作成する。原文の CLI 引数・接続設定・生の DB 例外・入力 JSON は記録しない。ログ初期化は引数解析や DB 接続より先に行う。

## 選択肢マスタ

ChoicePlanner は項目ごとに `View_vvplic_ChoiceList_{ReferenceType}_{SiteId}_{ColumnName}_{SiteName}` を作る。列名は本体 Choice と同じ Value / Text / TextMini。View は Sites.SiteSettings を参照時に DB の組込関数で展開する。選択肢の編集は View を作り直さずに反映し、選択肢の数だけ SQL が伸びることもない。

- SQL Server: OPENJSON で項目を取り出し、STRING_SPLIT の ordinal で行と区切りを分け、PIVOT で3列にする。TRIM の除去文字指定と ordinal のため SQL Server 2022 以降または Azure SQL、互換性レベル 130 以上を要求し、満たさなければ停止する。
- PostgreSQL: jsonb_array_elements、regexp_split_to_table WITH ORDINALITY、後読み付きの regexp_split_to_array、DISTINCT ON を使う。バックスラッシュは E'' 文字列に限定し、standard_conforming_strings に依存しない。
- MySQL: JSON_TABLE で項目を取り出し、改行数ぶんの JSON 配列を JSON_TABLE の FOR ORDINALITY で行番号にし、SUBSTRING_INDEX で分ける。sql_mode に依存しないよう、SQL 中にバックスラッシュを書かない。

本体の既定規則（CRLF を LF にして行に分け、前後の空白を除き空行を捨てる、`\` が前にないカンマで区切り `\,` をカンマへ戻す、行をカンマで単純に分けた先頭要素が重なれば最初の行を採用）を3 DB で再現する。General.json の区切り・置換規則が既定と異なる場合は DB 側で同じ結果を保証できないため停止する。計画時に動的参照（`[[...]]`）があれば停止し、適用後に追加された動的参照行は View から除外する。一覧 View と整理の対象範囲を分ける。

## 稼働中の環境への適用

運用中の DB に対して業務を止めずに実行できることを要件とする。DDL がロック待ちの列に並び続けると、後から来た業務クエリまで待たされるため、待機には必ず上限を設ける（`--lock-timeout`、既定5秒、1〜3600秒）。上限に達した DDL は変更なしで中止されるので、間隔を空けて2回まで再試行し、それでも取れなければ停止する。

- SQL Server: ONLINE = ON で作成する。2022 以降と Azure SQL では WAIT_AT_LOW_PRIORITY (ABORT_AFTER_WAIT = SELF) を付け、待機中も業務の更新を先に通す。ONLINE に対応しないエディションは黙ってオフライン作成へ切り替えず停止する（エラー 1712）。セッションには SET LOCK_TIMEOUT を設定する。
- PostgreSQL: CREATE / DROP INDEX CONCURRENTLY は業務の読み書きを妨げない。既存トランザクションの終了を待つ途中で打ち切ると INVALID 索引が残るため、この操作だけ lock_timeout を設けない。View の作成・置換・削除には lock_timeout を設ける。
- MySQL: ALGORITHM=INPLACE, LOCK=NONE で作成・削除する。開始と終了で排他メタデータロックを短時間要求し、待機中は後続のトランザクションを止めるため lock_wait_timeout を設ける。

`--offline` はロックを伴う作成を明示的に許可する指定で、保守時間帯に使う。

ハッシュの正規形は Table|Column:Direction:Prefix:Pattern|...。Direction は A / D、Pattern は True / False。例：Results|SiteId:A:0:False|ClassA:A:0:False|UpdatedTime:D:0:False|ResultId:D:0:False。ユーザー向けの規則は [生成ルール](生成ルール.md) を参照。
