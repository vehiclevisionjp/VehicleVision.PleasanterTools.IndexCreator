# 運用手順

本体設定のバックアップと DB の復旧手順を用意し、代表ビューの追加前の応答を計測する。DB の owner 相当で接続する。接続文字列をコマンドラインへ書かない。

## 設定の優先順位

`INDEXCREATOR_DBMS` と `/dbms` で DBMS を上書きできる。通常は本体 Rds.json を使う。

接続文字列は次の最初の空でない値。先頭以外は本体 Initializer の owner 接続と同じ順序。

1. INDEXCREATOR_CONNECTION_STRING
2. Rds.json の OwnerConnectionString
3. Service.EnvironmentName + `_OwnerConnectionString`
4. Service.Name + `_Rds_<Dbms>_OwnerConnectionString`
5. Service.Name + `_Rds_<Dbms>_ConnectionString`
6. Service.Name + `_Rds_OwnerConnectionString`
7. Service.Name + `_Rds_ConnectionString`

`#ServiceName#` はサービス名へ置換する。SaConnectionString は使わない。DB のメッセージ・接続文字列・例外詳細はコンソールへ出さない。TLS は各ドライバの既定を使い、証明書検証をアプリから無効化しない。検証コンテナのみ SQL Server の接続に TrustServerCertificate を指定している。

## 更新する

1. サイト編集と CodeDefiner 実行を終了する。
2. `plan /prune /output plan.sql` で計画を確認する。
3. 候補列の長さ・頻出値・代表ビューの実行計画を確認する。
4. `_rds /prune /y` を実行する。
5. `plan /prune` で不足・不要がないことを確認し、代表ビューと登録・更新の応答を再計測する。

**実行ファイル名の変更:** v0.3.0 から DLL 名が `IndexCreator.dll` から `VehicleVision.PleasanterTools.IndexCreator.dll` に変わります。旧版の `IndexCreator` フォルダへ上書き展開すると旧 DLL が残るため、フォルダを入れ替えてください。`dotnet IndexCreator.dll ...` と呼ぶ自動実行のスクリプトやジョブも、新しい DLL 名へ直してください。ZIP 名も `VehicleVision.PleasanterTools.IndexCreator-<バージョン>-<RID>.zip` に変わります（展開後のフォルダ名 `IndexCreator` は変わりません）。ダウンロードを自動化している場合は URL も直してください。

追加に失敗すると非ゼロ終了。既に成功した追加は残る。PostgreSQL では INVALID 索引が残る場合があり、再実行で修復する。CodeDefiner による索引消失も `_rds /y` で補完する。

最小件数を変更すると対象候補が変わる。`/prune` は現在の対象範囲で不要と判定した管理索引を削除するため、定期運用では最小件数・prefix 長・フィルタ欄オプションを固定する。

`/output` は適用するかどうかに関係なく検査時点の SQL を保存する。実行済み SQL を再適用するより、本アプリを再実行する方が現在の定義との衝突を検知できる。索引名を別ツールで変更した場合は本アプリの管理対象から外れる。

SQL Server のキー上限を超える長い分類値は、追加後の INSERT / UPDATE を失敗させる場合がある。PostgreSQL の B-tree にも行サイズの上限がある。MySQL は prefix 長を変えると別定義になる。ロック待ちは `/lock-timeout` の秒数で打ち切るが、MySQL のメタデータロックや DROP の待機中は後続の処理が一時的に待たされる。オンライン作成に対応しない SQL Server のエディションでは停止するため、`/offline` を付けて保守時間帯に実行する。詳しくは [利用ガイド](利用ガイド.md#稼働中の環境で実行する) を参照。

終了コード: 0=成功/計画完了、1=ファイル等の一般エラー、2=設定/引数/整合性エラーまたは確認キャンセル、3=DB エラー、130=中断。
